# 0002. ツールは2本。モデルに見せる面を予算で拘束する

## 状態

採用

## 文脈

`pi-subagents` の `subagent` ツールは description 5,240 文字、parameters 12,985 文字(トップレベル
82 プロパティ)、管理アクション49種。ツール定義は毎リクエスト送られるため、これは恒久的な文脈税である。
upstream は 0.71.0 で遅延ロード用の `subagents_enable` を追加したが、これは膨らんだ面を隠す対症療法で、
有効化後は同じコストを払う。

(数値の測定方法は [foundation.md](../foundation.md) の「計測方法」を参照。)

## 決定

モデルに見せるツールを `spawn_agents`(親のみ)と `message_agent`(子のみ)の2本に固定し、
**description とパラメータスキーマの合計**をトークン換算して予算で拘束する。

- 計測対象は `名前 + description + JSON.stringify(parameters)`。ツール名も毎回送られるため含める。
- トークン数は文字数 ÷ 4 の概算(依存を増やさないため)。
- 予算は **400 トークン**(実測 308)。agent カタログ注入には別枠で 120 トークンの上限を置く。
- 400 とした根拠は、実測 308 に対して「説明文の言い回し変更では壊れず、ツール追加や引数群の追加では
  落ちる」幅にすること。予算の引き上げは `docs/adr/` への記録を伴う。

## 結果

- `subagent` 比でツール面は約 94% 減(約 5,000 → 308 トークン)。
- 遅延ロード機構を必要としない。遅延ロードの目的は「有効化していないセッションの文脈を守ること」
  であり、常時ロードできる大きさなら目的自体が消える。予算テストはその大きさを保つ手段であって、
  遅延ロードの代替機能ではない。
- ツールを増やす/引数を増やす変更は、必ず予算テストの更新を伴う。予算は黙って上げられない。
- 子は `spawn_agents` を受け取らないため、委譲の深さが 1 に固定される(副次的な安全境界)。
- **失う機能**: 管理アクション49種が担っていた一覧・状態・中断・再開・スケジュールなどの操作は
  存在しない。同等の情報は Pi 本体のセッション表示とツール結果でしか得られない。
  意図的な取捨であり、機能単位の比較は [research.md](../research.md) にある。

## 再検討の条件

- 新機能がどうしても3本目のツールを必要とし、既存2本への統合が引数上限(3個)を超える場合。
  そのときは予算の引き上げと引き換えに、削る機能を同時に決める。

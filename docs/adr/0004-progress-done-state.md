# ADR 0004: 進捗表示に子ごとの `done` を出し、経過時間は子ごとに止める

- 状態: 採用
- 日付: 2026-09-27
- 対象: `spawn_agents` の進捗表示(`RunProgress.elapsed_ms` と子チャネルの `settledAt`)

## 背景

- 進捗フレームは呼び出しが返るまで起動済みの全 run を毎回含む。1体が先にターンを終えても、
  その行は最後の活動ラベル(`writing` など)のまま残り、完了を判別できなかった。
- 経過時間は呼び出し開始からの共通の値だったため、終了した子の行でも増え続けた。
- 子セッション SDK は、自動リトライ・コンパクション・キュー済みの作業が残らない時点で `agent_settled` を発行する。
  次のターンは `turn_start` で始まる。

## 決定

1. チャネルは `agent_settled` で `settledAt` を記録し、`turn_start` で消す。
   `agent_settled` の活動ラベルは `done` にする。
2. 進捗の経過時間は子ごとの起動時刻から測り、`settledAt` があればそこで止める。
3. `done` は子のターンが終わった状態を意味する。
   兄弟からのメッセージで新しいターンが始まれば `thinking` などに戻り、経過時間も再開する。

## 理由

- セッションイベントを状態の正とする: ターン解決(`prompt()` の解決)で run を終了扱いにすると、
  その後に兄弟メッセージで起きたターンを反映できない。イベントなら再開と再度の `done` が同じ経路になる。
- 子の表示は既存の1秒ごとのフレームと `snapshot()` に乗せる。run ごとのタイマーやポーリングを足さない。
- 経過時間は各行がその子の起動からの経過時間を示す方が、呼び出し全体の値より表示の意味が明確になる。

## 帰結

- 全 run が返るまで、完了した子は `done` と停止した経過時間で表示され続ける。
- 兄弟からのメッセージで起きたターンも同じ行で表現される(`thinking` → `done`)。
- エラーや中断でターンが終わった子も `done` になり、失敗は呼び出しの結果で示す。

## 代替案

| 代替 | 却下理由 |
|---|---|
| `agent_end` で `done` にする | リトライやキュー済みの作業の前に発行され、まだ働く子を完了に見せる |
| `prompt()` の解決時に run を終了扱いにする | その後の兄弟メッセージのターンを反映するには run の再開を別経路で配線する必要がある |
| 呼び出し全体の経過時間を続ける | 完了した行の時計が進み続け、その子の所要時間を示さない |

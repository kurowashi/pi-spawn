# 0005. 配送を1経路にし、誘発ターンは spawn 呼び出しが待つ

## 状態

採用

## 文脈

兄弟宛メッセージの配送は、当初 `isStreaming()` を見て「実行中なら `steer()`、そうでなければ
`followUp()`」と使い分けていた。しかし Pi の `AgentSession.followUp()` はキューに積むだけで、
完了済みセッションの次ターンを開始しない。キューを消費するのは実行中 run のループだけなので、
待機中の兄弟へのメッセージは誰にも処理されない。

実機確認(pi-spawn の AGENTS.md にある手動スモークテスト)では、先に完了させた兄弟へ
`wait: true` で送ると `no reply within 120000ms` で失敗した。README は「待機中の兄弟には
次のターンで届く」と約束しており、実装が追いついていなかった。

Pi には「待機中ならターンを開始し、実行中なら安全点で割り込む」を1回で行う
`AgentSession.sendUserMessage(text, { deliverAs })` がある。ターンか queue かの判定と投入は
同一同期ブロックで行われるため、settle と配送の競合も実装側で持たなくて済む。

## 決定

1. 配送は `sendUserMessage({ deliverAs: "steer" })` の1経路にする。実行中/待機中の分岐は持たない。
2. 配送が開始したターン(誘発ターン)は `RunHandle.induced` に記録し、`spawn_agents` が
   全誘発ターンの完了を待ってから返る。`timeout_ms` は呼び出し全体で1本のタイマーにする。
   sender は返信(`wait: true`)だけを受け取って先に進める。
3. 誘発ターンの失敗は、その宛先 run の結果に `delivery turn failed: ...` として付ける。
   `wait: true` の送信者には配送自体の失敗として即時にも返る(二重に見えるが、それぞれ別の run の事実)。

## 結果

- 待機中の兄弟へ送っても新しいターンが始まり、`wait: true` で返信が返る。
- 既存の意味は変えない: `wait: true` は相手の最初のアシスタント発話で返り、`wait: false` は
  配送を投げて送信者のターンを続ける。相手のターン完了は spawn 呼び出しが受け持つ。
- 相互にメッセージする相談でも、返信が最初の発話で解けるため、待ちの循環で止まりにくい。
- 副次: `sendUserMessage` は既定でテンプレートを展開しないため、子のメッセージ本文が
  スキル/プロンプトテンプレートとして解釈されたり `/` コマンド判定でエラーになったりしなくなる。

## 再検討の条件

- 誘発ターンが長く spawn 呼び出しが伸びすぎる場合(`timeout_ms` による中断で足りるか)。
- 誘発ターンの失敗の帰属。現在は宛先 run の結果に付けるが、送信側へ寄せるべき実例が出た場合。
- Pi 側に配送専用のより良い API(ターン開始の通知など)が入った場合。

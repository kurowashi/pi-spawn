# ADR 0013: agent 定義の本文で `@path` を展開し、pi-import と同じ形式で追記する

- 状態: 採用
- 日付: 2026-10-14
- 対象: agent 定義の本文と、`createChildChannel` が子に渡す追加プロンプト

## 背景

- 子の定義本文は、子の追加プロンプトとして固定の文字列で渡される。共通の指示を複数の定義で共有するには、本文へ写すしかない。
- pi-import は context file の `@path` を Claude Code 2.1.287 と同じ規則で展開する。同じ書き方を定義本文でも使えれば、利用者は書き方を覚え直さずに済む。

## 決定

1. 定義本文の `@path` を、子を起動するたびに展開する。展開の規則（抽出・4 ホップ・重複排除・サイズ・拡張子）は pi-import と同じにする。
2. 本文は書いたまま残し、展開した参照先を pi-import と同じ `MEMORY_PROMPT` と `Contents of <絶対パス> (...)` のブロックとして本文の後ろに付ける。
3. 本文直下の参照は子の `cwd` 基準で解決する。ネストした参照は、読み込んだファイルのディレクトリ基準とする。
4. 定義が `agentDir` 配下（`agentDir/agents/`）なら `user`、それ以外（プロジェクトの `.pi/agents/`）なら `project` として説明文を付ける。参照は親の種別を継承する。
5. 展開のコードは pi-spawn に複製する。実行時依存は増やさない。

## 理由

- 展開は起動時に行う。定義の解決（カタログ）は毎ターン走るため、そこで読むと参照先の変更が反映されず、子の `cwd` も分からない。起動時なら最新のファイルを子の作業ディレクトリ基準で読める。
- 本文を残して後ろに付けるのは、pi-import の出力と同じ並びにして、同じ説明で同じ結果を得るためである。
- 型を場所で決めるのは、pi-import の `user` / `project` の説明文が利用者の意図（個人の全体指示か、リポジトリで共有する指示か）を示すためである。
- 実行時依存ゼロを守るため、スキャナは複製する。pi-import を依存として取り込むと、配布と依存の検証（`test/contract/dependencies.test.ts`）が両方とも変わる。

## 帰結

- 定義本文の `@path` が、子のプロンプトに実際のファイル内容として入る。`@path` が解決しなければ本文は変わらない。
- 展開の規則を変えるときは、pi-import と pi-spawn の両方を見直す必要がある。複製元の規則はテストで固定している（`test/unit/import-scan.test.ts`、`test/unit/memory-import.test.ts`）。
- 包み（`system-reminder`）は付けない。pi-import の `wrapper` 設定は持ち込まない。設定を増やすと、最小の成立条件を超えるため。
- `replace` の定義では、展開後の本文だけがプロンプトになる。

## 代替案

| 代替 | 却下理由 |
|---|---|
| 展開をカタログ読み込み時に行う | 毎ターン走り、参照先の変更が反映されない。子の `cwd` も使えない |
| `spawn_agents` の `task` 文でも展開する | 今回の要求は定義本文に限る。`task` まで広げると、ツール説明とスキーマの予算（400 トークン）に触れる |
| pi-import を依存として取り込む | 実行時依存を持たない原則を破る。pi-import は Pi の context file 注入を前提とした拡張で、子の起動経路とは別の責務である |
| 展開したファイルを `system-reminder` で包む | 定義本文はすでにシステムプロンプトの一部で、包みを足しても区切りの情報は増えない。設定項目も増える |

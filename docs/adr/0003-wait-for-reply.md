# ADR 0003: 返信はターンとして届き、子は返信を待たない

- 状態: 採用 (2026-09-27 `wait_for_reply` を削除)
- 日付: 2026-09-27
- 対象: 削除した `message_agent` の `wait_for_reply` と `output` の意味

## 背景

- `message_agent` は `wait_for_reply: true` で、送信元の子が宛先の次の発話1回分を戻り値として
  受け取れた。宛先のタスク完了を待つものではなく、返信がなければ120秒でエラーになった。
- 待ちの循環は `hasInboundWait`(返信待ちを受けている run をさらに待てない)で禁止していた。
  この1ビットと拒否経路が、待つ関係を「親 → 全子」以外にもう1箇所作っていた。
- 結果(`output`)は最初のターンの発話で、配送で始まったターンの発話は反映されなかった。

## 決定

1. `wait_for_reply` を削除する。返信は宛先の新しいターンとして届き、送信元はブロックしない。
2. 子の結果(`output`)は、会話後の最新の発話にする。

## 理由

- 返信は run 宛てのメッセージであり、宛先の次の発話ではない。配送が既にターンを起こすため、
  送信元が待つ必要はない。
- 待ちの循環、120秒のタイムアウト、`nextAssistantText` の配管がすべて不要になる。
- 待つ関係が「親 → 全子(常に)」の1箇所だけになり、説明とテストが単純になる。

## 帰結

- 子は同一ターン内で返信を受け取れない。会話はターンで進む。
- 子ツールは 95 → 71 トークンに減った(計測: 319/400)。
- 結果は最初の発話ではなく最新の発話になる。

## 代替案

| 代替 | 却下理由 |
|---|---|
| `wait_for_reply` を残し、待ちの循環の禁止だけを続ける | 1ビットの状態と拒否経路が恒久的に残り、120秒のタイムアウトも必要になる |
| 返信待ちを宛先のタスク完了待ちに変える | 兄弟の完了は spawn の完了条件であり、子が待つと親の待ちと二重になる |

# ADR 0005: run に表示名を付け、統計とログを親の UI で見せる

- 状態: 採用
- 日付: 2026-09-28
- 対象: `tasks[].name`、進捗・結果の表示、`/spawn` コマンドとログビュー、`@earendil-works/pi-tui` 依存

## 背景

- run の識別は run id (8桁 hex) だけで、同じ agent を複数の役割で走らせても区別が読めなかった。
- 使用モデルと usage (input / output / cache / cost) は `RunProgress` に既にあったが表示していなかった。
  コンテキスト使用量は取得していなかった。
- 実行中の子は最新出力の1行しか見えず、全文は完了後に `pi --session` で開くしかなかった。
- 子セッションの JSONL はエントリごとに逐次追記され、拡張コマンドはストリーミング中でも即座に実行される。
  `spawn_agents` が親のターンを占有している間でも、コマンドから実行中の子を覗ける。

## 決定

1. `tasks[]` に任意の `name` を追加する。表示専用とし、宛先解決には使わない。
   未指定時は agent 名、同じ agent が複数いるときは `writer-1` のように連番にする。
2. 進捗行と結果の表示に表示名・モデル・コンテキスト使用量・コスト・usage を表示する。
   コンテキスト使用量・コスト・usage・経過時間はモデル向け `content` には入れず、`details` とツールレンダラで UI にだけ表示する。
   表示名とモデルは既存どおり結果の見出し `[name] run_id (model)` として `content` にも入る。
3. 子セッションの `getContextUsage()` を `ChannelSnapshot` と `RunProgress` に追加する。
4. ユーザー専用コマンド `/spawn` を追加する。引数なしは実行中 run の選択、
   `<target>` または `logs <target>` でログビューを開く。
5. ログビューは子セッションの JSONL 末尾を0.7秒ごとに読み、タグ付きの行として表示する。
   `Esc` で閉じ、`f` で最新に追従し、`t` で最古に移動する。
6. `@earendil-works/pi-tui` を devDependency (`0.87.1`) と peerDependency (`*`, optional) に宣言する。

## 理由

- 名前を表示だけに使えば、run id の解決規則と `message_agent` の意味を変えずに済む。
- モデル向け `content` に統計を足すと全ターンのコンテキスト税になる。
  モデルは usage を知る必要がなく、UI 表示は `details` で足りる。
- ログはセッションファイルを正にする。メモリ上のバッファを持たず、完了後も同じ内容を見られる。
- コマンドはツール予算 (400トークン) を消費しない。ストリーミング中の唯一の操作窓口になる。
- Pi は拡張へ `@earendil-works/pi-tui` を仮想モジュールとして供給するため、実行時依存は増えない。
  import allowlist (`ALLOWED_PEER_DEPENDENCIES`) には既に含まれている。

## 帰結

- `tasks[].name` は重複してもよい。宛先には run id か一意な agent 名を使う。
- 進捗行が長くなる。プレビューは従来どおり80文字で切る。
- `/spawn` の一覧に出るのは実行中の run だけ。完了後の全文は `session_file` を `pi --session` で開く。
- ログビューは TUI 専用。RPC では要約の通知だけになり、print / JSON では何も表示しない。
- ツール定義は 319 → 344 トークンに増えた(計測: 344/400、`tasks[].name` の分)。
- peer の allowlist は変更不要で、devDependency の allowlist に `@earendil-works/pi-tui` を追加した。

## 代替案

| 代替 | 却下理由 |
|---|---|
| `tasks[].name` を宛先にも使う | 名前の解決規則と重複時の拒否経路が増える。宛先は run id で足りる |
| 自動連番だけで識別する | 役割が読めず、名前を付ける目的を満たさない |
| 統計をモデル向け `content` に載せる | 全ターンのコンテキスト税になり、モデルには不要 |
| 実行ログをメモリに保持して表示する | 完了後に消え、セッションファイルと二重管理になる |
| ウィジェット常駐で最新行を表示する | スクロールできず、ログの確認手段にならない |
| キーバインドでログを開く | 発見できず、TUI 以外では使えない |
| 完了後も `/spawn` から開けるようにする | セッション探索と `cwd` 一致の規則を持ち込む。まず実行中の確認に絞る |
| ログを `pi-tui` に依存せず自前描画する | 幅計算・キー解釈・スクロールの再実装になる。Pi が部品を供給している |

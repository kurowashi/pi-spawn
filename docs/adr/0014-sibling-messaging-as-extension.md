# ADR 0014: 兄弟間メッセージを最小の成立条件から外し、拡張として扱う

- 状態: 採用
- 日付: 2026-10-17
- 対象: `DESIGN.md` の「目指すべきところ」（達成状態・最小の成立条件・拡張）、`README.md` の構成

## 背景

- pi-spawn の中核は、独立したタスクの並列委譲と、子の作業の再開（session id と entry id）である。
- 兄弟間の `message_agent` は、同じ呼び出しの子同士の直接連絡である。受け手は新しいターンとして受け取り、返信は同じターン内では返らず、親は実行中に介入できない。
- 利用者が中核の機能として読めるよう、README は兄弟間メッセージを概要と冒頭の図に出していた。
- DESIGN は兄弟間メッセージを達成状態と最小の成立条件に並べていた。そのため、README で中核を前に出すと、設計文書と説明の重みが食い違った。

## 決定

1. 兄弟間の `message_agent` は残す。ツールの面・挙動・宛先の形式は変えない。
2. `DESIGN.md` の達成状態と最小の成立条件から外し、「拡張」として書く。拡張は、最小の成立条件を崩さず、達成状態への寄与を実測で示せるときだけ維持する。
3. `README.md` では、兄弟間メッセージを末尾の「おまけ」に置く。冒頭の図と概要には出さない。詳細は `docs/reference.md` に置く。

## 理由

- 中核の価値（並列委譲・文脈を広げない・再開・進行の観測）は、兄弟間メッセージが無くても成り立つ。成立条件を中核に限ると、設計の判断基準と README の説明が一致する。
- 兄弟間メッセージは、同一ターン内で返信が返らない、親が介入できないなどの制約を持つ。中核と同じ重みで説明すると、利用者が期待しすぎる。
- 削除は選ばない。利用者が連絡を必要とする場面はあり、現時点で使用実績を集計して不要と判断した証拠はない。削除する場合は、使用実績の計測（`docs/manual-checks.md` のツール面レビュー）を先に行い、別の ADR で決める。

## 却下した代替

| 代替 | 却下理由 |
|---|---|
| 最小の成立条件に残し、README だけ降格する | 設計文書と説明が食い違う。中核の判断基準に、中核でない機能が残る |
| 機能を削除する | 使用実績の計測がまだなく、削除の根拠を欠く。削除は別の決定として扱う |
| 兄弟間メッセージを別のツールや拡張パッケージへ分離する | 1プラグイン内で完結する機能を分けると、子の宛先一覧とツール面の両方に変更が入る。今回の目的（説明の重みを直す）に対して過大 |
